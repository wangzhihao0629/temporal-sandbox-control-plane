Sandbox Control Plane

A Temporal workflow leases a VM, drives it through eleven versioned activities, and hands it back. The workflow never runs on the machine it uses.

Verified against sandbox/ at commit 6049106 (2026-09-10) Original diagram corrected in 5 places — flagged inline

Task queues

orchestrator-queue

The demo workflows and their two orchestrator-side activities, read_envelope and publish_summary.

sandbox-manager-queue

acquire and release, plus the scheduled reconciler workflow.

sandbox-vm-<vm_id>

One queue per VM — only that VM's own agent polls it, running the exec/file activities.

    WF->>MG: sandbox.v1.acquire(pool demo, request_id)

    WF->>VA: exec_start clone
    VA->>JB: sudo -u agent bin/runner clone
    JB->>S3: seed or restore repo.bundle, write clone envelope
    WF->>VA: exec_wait (heartbeats every 5s, touches the lease)
    VA-->>WF: ExecResult exited 0
    WF->>S3: orchestrator.read_envelope → {turn: 0}
    loop until tests pass or max_turns
        WF->>VA: exec_start / exec_wait turn
        VA->>JB: bin/runner turn --feedback-uri (last test report)
        JB->>S3: commit, repo.bundle, session.json, turn envelope
        WF->>VA: exec_start / exec_wait lint
        WF->>VA: exec_start / exec_wait test
        WF->>S3: read_envelope ×3 (failures are data, not errors)
    end
    WF->>VA: exec_start / exec_wait export
    WF->>VA: sandbox.v1.get_file session.patch → sandbox-out
    WF->>S3: orchestrator.publish_summary summary.json
    WF->>MG: sandbox.v1.release(lease_id, recycle)
    Note over VA: heartbeat loop sees recycling → wipes workspace → idle (agent-driven, no workflow involved)

Twenty-nine activities for a two-turn session: one acquire, one artifact, eight steps of start/wait/read, one file, one summary, one release. If the VM dies mid-turn, exec_wait raises LeaseLost, release runs from the finally, and the loop leases another VM whose clone restores the bundle saved after the last finished turn.

A VM's life in the registry

stateDiagram-v2
    [*] --> booting: reconciler launches\n(deficit = floor + pending − available)
    booting --> idle: agent registers, worker up
    idle --> leased: acquire\n(conditional write, oldest first)
    leased --> recycling: release (recycle)
    leased --> terminating: release (destroy)
    leased --> draining: agent's own SIGTERM handler\n(chaos "stop" triggers this drain)
    recycling --> idle: agent wipes workspace\n(heartbeat loop — agent-driven)
    draining --> terminated: worker stopped
    terminating --> terminated: worker stopped
    idle --> terminated: write_off\n(instance gone / stale heartbeat)
    booting --> terminated: write_off
    leased --> dead: provider reports the instance gone
    terminated --> [*]: swept after sweep_after_seconds

Every transition is a conditional write on one DynamoDB row, so two managers racing one VM cannot both win a lease. The reconciler runs launch, write-off, orphan-release, and scale edges on a schedule; the agent runs boot, wipe, and drain; the manager runs acquire and release.

Corrected Eight states, not six-plus-a-write-off. booting, idle, leased, recycling, draining, terminating, dead, terminated. write_off() writes terminated directly (guarded so it can't fire twice) — there's no separate "write-off" state, and dead is its own provider-reported terminal, distinct from a normal terminated. sandbox/registry/schema.py:18–27 · registry/client.py:429–460
Corrected recycling → idle is the agent's call, not the manager's. The heartbeat loop wipes the workspace and flips the row with a conditional expect="recycling" update — the manager is never involved in that edge. sandbox/vm_agent/heartbeat.py:45–57
Corrected draining comes from the agent's own shutdown handler, not from anything chaos-specific — make chaos-stop just sends the SIGTERM that trips it. sandbox/vm_agent/runtime.py:108–111 · manager/chaos.py:3–4
Corrected "Swept after 600s" is the local/demo profile only. Tunables sets 600s for local, 3600s for prod, and 2s for test. sandbox/manager/reconciler.py:65,69,73

What the demo proves, and where

  • 01Leases outlive workers. Kill the orchestrator mid-turn — exec_wait is retried and reattaches to the job record on the VM's disk. No rerun.
  • 02A dead VM is a retry, not a failure. make chaos-kill on the leased VM; the session finishes on a second VM with two lease attempts and the same turn count.
  • 03The fleet heals itself. The reconciler tops up to the floor from nothing, writes off dead VMs, releases orphaned leases, scales out under pending demand, scales in after a cooldown.
  • 04Everything is watchable. The dashboard on :8600 joins the registry, provider, Temporal, and S3 into one page with a live event feed; the Temporal UI on :8233 shows every activity on its queue.
